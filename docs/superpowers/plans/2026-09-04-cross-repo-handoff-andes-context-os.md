# Andes Context OS Cross-Repo Handoff V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Andes Context OS strictly consume a territorial `question-research-handoff/v0.1`, preview an explicit research intent without guessing missing semantics, add the minimal `decision_support` activity, and export a conservative `ACTOR_NEED_HYPOTHESIS` candidate through `research-opportunity-handoff/v0.1`.

**Architecture:** Andes owns only the territorial leg. A stdlib-only contract module validates the upstream JSON snapshot, a pure intake preview requires operator-supplied domain/activity/goal before constructing `ResearchIntent`, and a pure exporter converts an existing `OpportunityHypothesis` into Contract 2 without promoting its status or resolving actors/evidence by inference. Territorial scope remains a separate explicit requirement.

**Tech Stack:** Python 3.11+, standard library only, dataclasses/StrEnum, existing Andes validation helpers, pytest.

**Spec:** Canonical spec is in `juanmanueltorres-creator/question-radar` at `docs/superpowers/specs/2026-09-04-cross-repo-problem-opportunity-handoff-v0.1-design.md`.

## Global Constraints

- Runtime dependencies remain empty.
- No import from `question-radar` or `opportunity-os`.
- Existing `ResearchDomain`, `ResearchIntent`, `TerritorialScope`, evidence, movement, asset, and `OpportunityHypothesis` serialized records remain valid.
- Add exactly one activity value: `ResearchActivity.DECISION_SUPPORT = "decision_support"`.
- `TERRITORIAL_RESEARCH` is the only Contract 1 route Andes accepts in V0.1.
- Domain, activity, research goal, and territorial scope are never inferred from free text.
- The upstream handoff is context, not evidence.
- Upstream source freshness is always exposed as `AS_OF_EXPORT`; Andes does not call Question Radar to revalidate it.
- Contract 2 candidate kind emitted by Andes is exactly `ACTOR_NEED_HYPOTHESIS`.
- Preserve `OpportunityHypothesis.status` verbatim; no export/import transition is allowed.
- Preserve actor refs, supporting evidence refs, assumptions, and missing context exactly and in order.
- Empty actor refs are valid research; they disable actor-oriented downstream dispositions rather than invalidating the artifact.
- No buyer, procurement, hiring, willingness-to-pay, or contact-permission claim may be synthesized.
- Unknown fields, unsupported contract versions, and non-territorial routes fail closed.
- No API, database, crawler, LLM, embedding layer, or network client is added.
